# 基于 LangChain 的 RAG 企业级知识库问答系统 —— 毕业设计文档

## 1. 选题背景与意义

电商平台商品信息量大、更新频繁，客服与用户都需要快速、准确地获取商品知识（参数、功能、售后政策、物流规则等）。传统检索依赖关键词匹配，无法理解自然语言语义；直接使用通用大模型问答又会产生"幻觉"，回答不可信。

本课题基于 **LangChain** 框架构建 **RAG（Retrieval-Augmented Generation，检索增强生成）** 企业级知识库问答系统：先检索商品知识库中的相关内容作为依据，再由大模型基于依据生成回答，并在回答中**展示引用片段**，实现"有据可查、可溯源"的智能问答。系统面向浏览器使用，支持知识库管理、多用户多会话与历史持久化，并应用多种性能优化手段达到企业级使用标准。

## 2. 需求分析

### 2.1 功能需求

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F1 | 浏览器知识库管理 | 管理员可上传商品文档（PDF/Word/TXT/MD），系统自动解析入库 |
| F2 | 浏览器知识库问答 | 用户以自然语言提问，系统结合知识库回答 |
| F3 | 引用片段展示 | 回答中标注 [编号] 引用，可查看对应知识库原文 |
| F4 | 多用户多会话 | 每个用户拥有独立的多会话，互不可见 |
| F5 | 会话历史持久化 | 不同时间段登录均可找回历史对话 |
| F6 | 注册登录与改密码 | 基础账号体系，bcrypt 加密存储 |
| F7 | 管理员账号 | 种子账号 admin / 123456，仅管理员可管理知识库 |
| F8 | 性能优化 | 缓存、异步入库、流式输出、前端分包等企业级手段 |

### 2.2 非功能需求

- **性能**：问答首字延迟低（SSE 流式）；检索命中缓存后毫秒级返回；入库不阻塞上传
- **可靠性**：文档入库失败有状态标记与错误信息；会话数据持久化
- **安全**：JWT 鉴权、密码 bcrypt 哈希、角色权限控制、跨用户数据隔离
- **可维护**：后端分层架构（core/db/models/schemas/crud/api/services），单元测试覆盖

### 2.3 环境约束（选题依据）

- 开发机无独立显卡 → 向量化与推理采用 **CPU 可运行**方案（fastembed + ONNX Runtime）
- 网络受限无法下载 Docker 镜像 → 全部依赖 **pip 安装**（Chroma 嵌入式向量库、SQLite），不引入容器
- 大模型采用**智谱 GLM-4-Flash 云端 API**（OpenAI 兼容、长期免费），Ollama 作为本地备选

## 3. 总体设计

### 3.1 系统架构

```
┌───────────────────────────── 浏览器 ─────────────────────────────┐
│  Vue3 + Element Plus 前端（登录/注册/首页/问答/知识库管理/看板）  │
│  会话侧栏 · 流式问答 · 引用折叠卡 · 路由守卫 · JWT 携带            │
└──────────────────────────────┬──────────────────────────────────┘
                               │ HTTP + SSE（/api/v1）
┌──────────────────────────────▼──────────────────────────────────┐
│  FastAPI 后端（分层）                                             │
│  api（路由+依赖：auth/kb/chat/conversation/dashboard）           │
│  services（ingestion/retrieval/qa/llm/embedding/cache）          │
│  crud → models → SQLAlchemy（SQLite: users/documents/           │
│         conversations/messages）                                 │
│  Chroma 向量库（data/chroma，BGE 512 维）                         │
│  中间件：CORS / GZip / 请求耗时                                   │
└──────────────────────────────┬──────────────────────────────────┘
                               │ HTTPS
              ┌────────────────┴────────────────┐
              │ 智谱 GLM-4-Flash（OpenAI 兼容）  │
              └─────────────────────────────────┘
```

### 3.2 数据模型

- **users**：id / username / password_hash / role / created_at
- **knowledge_bases**：id / name / description
- **documents**：id / kb_id / filename / file_type / size / status / error_message / chunk_count / created_at / updated_at
- **conversations**：id / user_id / title / created_at / updated_at
- **messages**：id / conversation_id / role / content / refs_json（引用片段 JSON）/ created_at

## 4. 详细设计

### 4.1 文档入库管道（M2）

```
上传（管理员） → 白名单校验 + 50MB 限制 → 落盘 data/uploads
  → 后台任务：LangChain 加载器解析
      （PyMuPDFLoader / Docx2txtLoader / TextLoader）
  → 父子分块（父 800 / 子 200，RecursiveCharacterTextSplitter）
  → fastembed（BGE-small-zh-v1.5）向量化
  → Chroma 写入（metadata 含 document_id / filename）
  → 知识库版本号 +1（检索缓存失效）
```

### 4.2 混合检索（M3）

单一向量检索对专有名词、型号、数值不够敏感，采用 **两路召回 + RRF 融合**：

1. **向量召回**：Chroma 余弦相似度，语义匹配
2. **关键词召回**：jieba 分词 + BM25Okapi，精确匹配型号/名词
3. **RRF 融合**：`score = Σ 1/(K + rank)`，K=60，两路都命中的片段排名更高
4. **可选 Rerank**：fastembed Cross-Encoder 重排（配置开关，默认关闭避免额外模型下载）

### 4.3 问答与引用（M3）

- Prompt 组装：检索片段带 `[编号]` 注入系统/用户消息，强制"基于知识库回答并标注引用"
- **SSE 流式**：事件序列 `meta`（引用片段 + 会话 ID）→ `delta`（增量文本）→ `done`/`error`
- 前端 fetch 流式解析 + 打字机效果 + 引用折叠卡片

### 4.4 多用户多会话（M4）

- Conversation / Message 两张表按 `user_id` 隔离，接口层强制归属校验（跨用户访问返回 404）
- 问答时自动创建会话（标题取问题前 20 字），流式结束后将用户问题、助手回答、引用片段一并落库
- 会话列表按 `updated_at` 倒序；前端会话侧栏支持新建/切换/重命名/删除

### 4.5 认证与权限

- JWT（HS256，7 天有效期）+ bcrypt 密码哈希
- 依赖注入：`get_current_user`（登录态）、`require_admin`（管理员）
- 前端路由守卫：`meta.public` 免登录、`meta.admin` 仅管理员

## 5. 性能优化（M5）

| 手段 | 实现 | 效果 |
| --- | --- | --- |
| 检索结果缓存 | 进程内 TTL 缓存（300s/128 条），知识库版本号变化自动失效 | 高频问题秒回 |
| 查询向量缓存 | lru_cache 相同问题不重复 embedding | 节省推理 |
| GZip 压缩 | GZipMiddleware | 减小响应体积 |
| 请求耗时监控 | 中间件输出 X-Process-Time | 可观测 |
| 后台异步入库 | FastAPI BackgroundTasks | 上传不阻塞 |
| 前端分包 | manualChunks 拆 vue / element-plus | 首屏优化 |
| 分页 | 文档列表 / 会话列表均分页 | 大数据量友好 |

## 6. 测试

pytest 共 **63 个用例**，按正常 / 边界 / 异常三类设计，覆盖：

- 认证：注册、重复注册 409、弱密码 422、错误密码 401、改密码、非法 token
- 用户 CRUD：bcrypt 哈希盐、更新密码、重复用户名
- 知识库：上传白名单、50MB 限制、权限（401/403）、后台入库、删除
- 检索：RRF 融合、语义召回、空知识库
- 问答接口：鉴权、无 Key 提示、参数校验、会话归属
- 会话：创建/列表/重命名/删除、跨用户隔离、消息持久化往返
- 看板：admin 200 / user 403

测试隔离：临时 SQLite + 临时数据目录，不污染开发数据。

## 7. 部署

- **单机部署**：双击 `start.bat` 一键启动前后端；无需 Docker、无需显卡、无需外部数据库
- **生产建议**：更换 SECRET_KEY、Nginx HTTPS 反向代理、必要时扩展 Redis 缓存与 PostgreSQL

## 8. 总结与展望

本系统完整实现了基于 LangChain 的 RAG 企业级知识库问答，覆盖知识库管理、引用式问答、多用户多会话、历史持久化、权限体系与企业级性能优化，并通过 63 个单元测试与端到端联调验证。

展望：接入流式 Rerank 与多路召回优化、语义缓存、基于反馈的检索质量评估、向量库横向扩展（Milvus/Qdrant）等。
